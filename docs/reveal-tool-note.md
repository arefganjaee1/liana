# ابزار `liana-reveal-tool.html` — بازسازی شد، بعد به «عکسِ پخته‌شده» تغییر مسیر داد

## تاریخچه
1. اول: ابزار قدیمی (`liana-reveal-tool.html`) که فقط تو چت فرستاده شده بود، هیچ‌وقت کامیت نشده بود و گم شده بود. از نو ساختمش، این‌بار رو ریپو (`tools/liana-reveal-tool.html`)، با خروجیِ **کد CSS/مختصات** (شبیهِ نسخه‌ی قدیمی).
2. بعد، رو سایت افکتِ «شیشه‌ی مه‌آلود» با **CSS زنده** پیاده شد: `backdrop-filter: blur()` + `mask-image` بیضی‌شکل رو `.hero-marquee-track .tile`, `.svc-media`, `.svc-pair .half`، با مختصات از `focus`/`beforeFocus`/`afterFocus` تو دیتای `SERVICES`.
3. کاربر یه رفرنس واقعی (طراحیِ «REVEAL/UNSEEN» از Behance، دیزاینر Ductuyen) فرستاد: شیشه‌ی مات با بافتِ شیاردار/دون‌دون (نه بلورِ صاف) + پنجره‌ی **مستطیلی** (نه بیضی).
4. موقعِ بحث درباره‌ی پیاده‌سازیِ اون بافت با فیلترهای پیشرفته‌ی SVG (`feTurbulence`+`feDisplacementMap`)، صریح گفتم این ریسکِ همون باگِ کامپوزیتینگِ سافاری رو داره که قبلاً (بخشِ «باگِ سنگینیِ بصری/پرفورمنسِ سافاری» تو `plan-and-decisions.md`) کلی وقت گذاشتیم رفعش کردیم.
5. **کاربر ایده‌ی درست و کلیدی داد:** «ما قراره عکسِ دانلودشده رو بزاریم رو سایت، یعنی سافاری اصلاً نمی‌فهمه بلوره یا سادس.» یعنی به‌جای افکتِ زنده‌ی CSS، **خودِ عکس از قبل با افکت پخته بشه** (یه فایلِ تخت/flat)، بعد فقط به‌عنوانِ `<img>` ساده رو سایت بذاریم — صفر ریسکِ رانتایم، چون مرورگر فقط یه عکسِ معمولی می‌بینه.
6. بعد از دیپلوی، کاربر گزارش داد «ابزارمون بلور نمی‌کنه» — چون ابزار برای بلور از `ctx.filter = 'blur()'` استفاده می‌کرد که پشتیبانیِ سافاری ازش ناقص/بی‌صداست (بدونِ ارور، فقط هیچ کاری نمی‌کنه). با یه **باکس‌بلورِ دستیِ چندپاسه** رو خودِ `ImageData` جایگزین شد که مستقل از هر Canvas Filter API کار می‌کنه.
7. بعد از رفعِ باگِ بلور، کاربر دوباره همون رفرنسِ Behance رو فرستاد و گفت با تنظیماتِ فعلی نمی‌تونه اون ظاهر رو دربیاره. مشکلِ واقعی: بافتِ شیشه تو ابزار یه موجِ سینوسیِ **عمودی و جهت‌دار** بود (شبیهِ شیشه‌ی فلوتد/ریبد)، درحالی‌که رفرنس یه بافتِ **بی‌جهت و دون‌دونِ نامنظم** بود (شبیهِ شیشه‌ی سندبلاست‌شده/واقعاً مات). این تشخیصِ درست بود و رفعش کردیم (به بخشِ زیر نگاه کن).

## تصمیم نهایی (این دور، بسته شد ✓)
- **افکتِ شیشه‌ی مه‌آلود دیگه با CSS زنده ساخته نمی‌شه.** بلوکِ `backdrop-filter`/`mask-image` رو `.hero-marquee-track .tile::after`, `.svc-media::after`, `.svc-pair .half::after` کامل حذف شد؛ فیلدهای `focus`/`beforeFocus`/`afterFocus` و تابعِ کمکیِ `focusStyle()` هم از `site/index.html` حذف شدن.
- خودِ فایل‌های `assets/*.jpg` (`hero-after.jpg`, `hero-before.jpg`, `service-botox.jpg`, `hotspot-detail.jpg`, `result-detail.jpg`) از قبل با افکت **پخته و ذخیره شدن**: بلور + دونه‌ریزی + پنجره‌ی **مستطیلیِ** واضح با لبه‌ی نرم رو ناحیه‌ی موردنظر. (نسخه‌ی اولیه‌ی این batch با بافتِ شیارِ عمودی پخته شده بود؛ اگه لازم شد با ابزارِ جدید دوباره پخته بشن تا با بافتِ بی‌جهتِ جدید یکی باشن.)
- نسخه‌ی خامِ (بدونِ افکت) هر عکس، برای مرجع/بازسازیِ بعدی، تو `site/assets/originals/` نگه داشته شده.
- **ابزار `tools/liana-reveal-tool.html` کامل بازنویسی شد**: دیگه فقط کد/مختصات نمی‌ده — با کانواس، خودِ افکت رو زنده رو مرورگرِ کاربر می‌سازه و یه **فایلِ عکسِ نهاییِ آماده** (`.jpg`) می‌ده که مستقیم قابلِ‌استفاده‌ست.
  - **بلور**: باکس‌بلورِ دستیِ چندپاسه رو `ImageData` (تابعِ `blurCanvas`/`boxBlurPass`) — نه `ctx.filter`، چون تو سافاری بی‌صدا کار نمی‌کنه.
  - **بافتِ شیشه**: تابعِ `buildFrostLayer` — یه لایه‌ی نویزِ تصادفیِ per-pixel با شدتِ قابل‌تنظیم که با شعاعِ بلورِ کوچیک (۱.۸px) نرم می‌شه تا دون‌دونِ ریز و **بی‌جهت** بشه (نه شیارِ جهت‌دار/موجِ سینوسی مثلِ نسخه‌ی قبلی). مستقیم به‌اندازه‌ی خودِ عکس ساخته می‌شه (نه یه تایلِ کوچیکِ تکرارشونده) تا درزِ لبه‌ی تایل نداشته باشه. با `globalCompositeOperation='overlay'` رو لایه‌ی بلورشده اعمال می‌شه.
  - اسلایدرها: «میزانِ بلور»، «شدتِ بافتِ مات» (قبلاً «شدتِ شیار» بود، بعد از این تصحیح اسمش عوض شد)، «نرمیِ لبه».

## نتیجه برای روندِ کار از این به بعد
برای هر عکسِ جدیدی (خدماتِ دیگه، هر جای دیگه‌ی سایت) که قراره این افکت رو داشته باشه:
1. کاربر عکسِ خام رو تو `tools/liana-reveal-tool.html` باز می‌کنه، مستطیل رو رو ناحیه‌ی موردنظر می‌کشه.
2. دکمه‌ی «دانلودِ عکسِ نهایی» رو می‌زنه — یه فایلِ `.jpg` آماده می‌گیره.
3. همون فایلِ نهایی (+ اگه خواست، فایلِ خامِ اصلی برای آرشیو) رو برای من می‌فرسته.
4. من فایلِ نهایی رو مستقیم به‌عنوانِ `src` تو `SERVICES`/`detail` می‌ذارم — **دیگه هیچ کدِ CSS/مختصاتی لازم نیست**، چون افکت از قبل تو خودِ عکسه.

**درس‌های کلیدی:**
- وقتی یه افکتِ بصری روی عکس ثابته (نه واکنش‌گر به اندازه‌ی صفحه/تعاملِ کاربر)، پختنش تو خودِ فایلِ عکس (به‌جای CSS/فیلترِ زنده) هم ریسکِ کامپوزیتینگِ Safari رو صفر می‌کنه، هم دقیقاً همون ظاهرِ رفرنس رو می‌شه پیاده کرد، بدونِ محدودیتِ چیزی که CSS/backdrop-filter عملاً می‌تونه بسازه.
- تو کانواس هم باید مراقبِ APIهای نیمه‌پشتیبانی‌شده بود (`ctx.filter` رو سافاری بی‌صدا فیل می‌شه) — پیاده‌سازیِ دستی رو `ImageData` همیشه مطمئن‌تره.
- «بافتِ شیشه‌ی مات» یعنی نویزِ بی‌جهتِ نرم‌شده (سندبلاست)، نه موجِ جهت‌دار/شیارِ منظم (فلوتد گلس) — این دو ظاهرِ کاملاً متفاوتی دارن؛ قبل از ساختِ یه بافتِ جنریک، باید دقیقاً چک کرد رفرنس کدومه.
