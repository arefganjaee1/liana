## فازِ ۱ — پنلِ مدیریتِ خدمات: ساخته، تست، و دیپلوی شد (نهایی شد ✓)

**بک‌اند (`server/`):** `node:sqlite` (بدونِ هیچ پکیجِ نیتیو) با جدولِ `staff`, `staff_hours`, `services`, `service_variants`, `service_images`, `service_staff`, `admin_users`, `sessions` (روی اسکلتِ قبلیِ `_meta`، `CREATE TABLE IF NOT EXISTS` غیرمخرب، `schema_version` از `0` به `1` رفت). دکتر فرناز به‌صورتِ خودکار به‌عنوانِ اولین پرسنل (`role='owner'`) سید می‌شه.

**احرازِ هویت:** کاملاً از built-inهای Node — بدونِ هیچ پکیجِ خارجی/نیتیو. `crypto.scryptSync` برایِ هشِ پسورد (سالت جدا به‌ازایِ هر کاربر)، `crypto.timingSafeEqual` برایِ مقایسه‌ی امن، سشنِ اپاکِ دیتابیس‌محور، پارسِ دستیِ کوکی (بدونِ `cookie-parser`)، کوکیِ `HttpOnly`/`SameSite=Lax`/۱۴روزه (`Secure` فقط رو production). میدل‌ورِ `requireAuth(role)` که `admin` رو سوپرستِ هر نقشی می‌کنه.

**آپلودِ عکس:** `multer` (نسخه‌ی ۲.x — نسخه‌ی ۱.x چندتا آسیب‌پذیریِ شناخته‌شده داشت، از اول با نسخه‌ی امن‌تر رفتیم — درسِ #۴۰)، ذخیره رو دیسک با نامِ رندوم، محدودیتِ ۸ مگابایت و فیلترِ نوعِ فایل.

**پنلِ ادمینِ فرانت (`server/admin/`):** فرانتِ استاتیکِ ساده پشتِ همون سرور (بدونِ فریم‌ورک/بیلد) — `login.html`، `services.html` (لیست + مودالِ افزودن/ویرایش با variantها/چک‌لیستِ پرسنل/گریدِ عکس)، `staff.html` (لیست + مودالِ ساعتِ کاریِ هفتگیِ RTL-درست، با هدرِ ستون که بعداً برای وضوح اضافه شد).

**تست:** کاملِ end-to-endی — `curl` رو تمامِ endpointها (لاگین/سشن/۴۰۱/۴۰۳ صحیح، CRUDِ خدمات، variantها، تخصیصِ پرسنل، آپلود/حذفِ عکس، حذفِ کسکِیدیِ عکس‌ها موقعِ حذفِ خدمت + پاک‌شدنِ فایلِ فیزیکی)، و یه اسکریپتِ Playwright که کلِ فلوی UI (لاگین → ساختِ خدمت → variant → تخصیصِ پرسنل → آپلودِ عکس → پرسنل → ساعتِ کاری → خروج) رو با اسکرین‌شات تأیید کرد — هم تو سندباکسِ ابری هم مستقیم رو مکِ خودِ کاربر (`npm install` و اجرای واقعی از طریقِ پلِ دستگاه).

**دیپلوی:** `server/src/*`, `server/admin/*`, `server/scripts/create-admin.mjs`, `server/package.json`/`package-lock.json` (با `multer` اضافه‌شده)، `server/.gitignore` (آپدیت شد تا `data/uploads/*` هم نادیده گرفته بشه، فقط `.gitkeep`)، و `server/README.md` (آپدیت‌شده با وضعیتِ فازِ ۱ و راهنمایِ اجرا) — همه رو مسیرِ ریپویِ واقعیِ کاربر نوشته و `git add` شدن. منتظرِ commit/push کاربر از GitHub Desktop.

## تستِ واقعیِ کاربر رو فازِ ۱ — سه باگِ واقعی پیدا و رفع شدن (نهایی شد ✓)

بعد از دیپلویِ فازِ ۱، کاربر خودش رو مکِ واقعیش (نه سندباکسِ من) شروع به تستِ دستیِ کاملِ پنل کرد و طیِ چند دور، یه چک‌لیستِ زنده (که هر بار با درخواستِ «چک لیست رو آپدیت کن» به‌روز می‌شد) موردبه‌مورد تیک خورد. سه باگِ واقعی (نه فرضی) تو همین فرآیند کشف و رفع شدن:

**باگِ ۱ — `Cannot GET /admin/`:** اولین‌بار که کاربر مستقیم `/admin/` رو باز کرد (نه `/admin/services.html`)، ۴۰۴ گرفت. علت: `express.static('/admin', ...)` وقتی مسیر بدونِ فایلِ مشخص درخواست بشه، دنبالِ `admin/index.html` می‌گرده؛ همچین فایلی وجود نداشت. **رفع:** `admin/index.html` جدید ساخته شد — یه صفحه‌ی خیلی سبک که با `fetch('/api/auth/me')` چک می‌کنه لاگین کرده یا نه و بر همون اساس به `services.html` یا `login.html` ریدایرکت می‌کنه.

**باگِ ۲ — تو «افزودنِ خدمت» نمی‌ذاشت عکس اضافه کنه:** کاربر اسکرین‌شات فرستاد که نشون می‌داد تایلِ «+ افزودنِ عکس» کلیک می‌خوره ولی دیالوگِ انتخابِ فایل باز نمی‌شه. ریشه: اون تایل یه `<label>` بود که هم `<select>` (نوعِ عکس) هم `<input type="file">` رو به‌عنوانِ فرزند دربر می‌گرفت؛ رفتارِ پیش‌فرضِ مرورگر برایِ `<label>` با چندین فرزندِ فرم‌دار اینه که کلیک رو فقط به **اولین** فرزند (یعنی `select`) می‌فرسته، نه به `input[type=file]` — پس کلیک‌کردن رو تایل هیچ‌وقت دیالوگِ فایل رو باز نمی‌کرد. **رفع:** `<label>` به `<div>` تغییر کرد، با یه event listenerِ صریح که `fileInput.click()` رو صدا می‌زنه (به‌جز وقتی کلیک رو خودِ `select` بوده). (درسِ #۴۱/#۴۲)

**باگِ ۳ — ساعتِ کاریِ پرسنل، ساعت/دقیقه جابه‌جا نمایش داده می‌شد:** کاربر اسکرین‌شات فرستاد که مثلاً «۰۹:۰۰» به‌شکلِ معکوس/غلط نمایش داده می‌شد. تشخیص: یه باگِ شناخته‌شده‌ی Safari/WebKit — ورودیِ بومیِ `<input type="time">` وقتی هیچ `dir` صریحی نداره و داخلِ یه صفحه‌ی `dir="rtl"`ه، می‌تونه ترتیبِ گروه‌های عددیش رو بصری معکوس کنه. **رفع:** `dir="ltr"` مستقیم رو خودِ `<input type="time">`های `startInp`/`endInp` تو `admin/js/staff.js` اضافه شد. **صادقانه به کاربر گفته شد:** من نتونستم این باگ رو تو Chromiumِ سندباکسِ خودم بازتولید کنم — رفع بر اساسِ تشخیصِ درستِ ریشه‌ی مشکل (نه تستِ بصریِ مستقیم) انجام شد.

## نقشِ manager، ایمپورتِ خدماتِ سایت، پلنِ دیپلویِ VPS (نهایی شد ✓)

**۱. نقشِ `manager` — «می‌تونه ویرایش کنه ولی حذف نه» (نهایی شد ✓):**
`requireAuth(role)` تو `server/src/auth.js` گسترش داده شد تا به‌جایِ فقط یه رشته، یه آرایه هم قبول کنه (درسِ #۴۴). یه ثابتِ جدید `WRITE_ROLES = ['admin', 'manager']` اکسپورت شد. تو `server/src/routes/services.js` و `server/src/routes/staff.js`، تمامِ روت‌های POST/PUT از `requireAuth('admin')` به `requireAuth(WRITE_ROLES)` تغییر کردن؛ هر دو روتِ **حذف** عمداً رو `requireAuth('admin')` موندن.

فرانتِ `admin/js/services.js`/`staff.js` هم آپدیت شد: دکمه‌ی «حذف» فقط وقتی `CURRENT_USER.role === 'admin'` رندر می‌شه (درسِ #۴۵).

**تأییدِ end-to-end:** حسابِ تستِ `manager` ساخته شد و با `curl` تست شد: منیجر تونست خدمتِ جدید بسازه و ویرایش کنه، ولی حذفِ خدمت/پرسنل رد شد (۴۰۳)؛ حسابِ `testadmin` همون حذف رو با موفقیت انجام داد.

**نکته‌ی ریزِ باقی‌مونده:** حذفِ variant/عکسِ داخلِ فرمِ خدمت از مسیرِ PUT/POST رد می‌شه (نه DELETE مستقیم)، پس منیجر می‌تونه یه variant رو از فرم پاک کنه، ولی نمی‌تونه یه *عکس* رو حذف کنه (درسِ #۴۵).

**۲. ایمپورتِ متنیِ خدماتِ سایت — «بله، الان اجرا کن» (نهایی شد ✓):**
اسکریپتِ `server/scripts/import-site-services.mjs`: آرایه‌ی `SERVICES` رو از `site/index.html` با regex استخراج و `new Function(...)` پارس می‌کنه، هر آیتم رو map می‌کنه (`title`, `description`, `category`, `variants`). `price`/`duration_minutes` خالی می‌مونن. idempotent‌ه (چک با `slug`).

۸ خدمت با موفقیت اضافه شدن. نکته: خدمتِ «لاغری و کاهشِ وزن» تو سایت دستهٔ `skin` داشت ولی محتواش لاغریه — عمداً همون دسته‌ی سایت نگه داشته شد (بدونِ ادیتوریال‌سازیِ خودسرانه).

**۳. مسیر/ساب‌دامینِ دیپلویِ بک‌اندِ VPS — «یه ساب‌دامینِ جدا» (پلن نوشته، بعداً اجرا شد ✓):**
ساب‌دامینِ انتخاب‌شده: **`panel.liana.arefprojects.ir`**. یه راهنمایِ کاملِ گام‌به‌گام نوشته و رو ریپو ذخیره شد (`server/deploy/panel.liana.arefprojects.ir.conf`, `server/deploy/README.md`).

## دیپلویِ واقعیِ پنل رو VPS — اجرایِ کاملِ تعاملی، سه مشکلِ واقعی، همه رفع شدن (نهایی شد ✓)

**مشکلِ ۱ — آسیب‌پذیریِ npm بدونِ رفعِ بدونِ‌شکستِ رسمی (`qs`):** `npm audit` رو سرور ۳ آسیب‌پذیریِ moderate تو `qs` نشون داد. **رفع:** `"overrides": {"qs": "^6.16.0"}` به `server/package.json` اضافه شد (درسِ #۴۶).

**مشکلِ ۲ — `node:sqlite` رو Node ۲۰ اصلاً وجود نداره:** VPS Node v20.20.2 داشت، `node:sqlite` حداقل Node ۲۲.۱۳+ لازم داره. **رفع:** `nvm` نصب شد (بدونِ لمسِ Node ۲۰ِ سیستمی)، Node ۲۴.۲۰.۰ گرفته شد، و پروسه‌ی pm2 با `--interpreter <مسیرِ مطلقِ Node ۲۴>` استارت شد (درسِ #۴۷).

**مشکلِ ۳ — رکوردِ DNSِ `panel.liana` اصلاً وجود نداشت:** `dig` رو مکِ کاربر (پشتِ VPN) گمراه‌کننده بود؛ تستِ واقعی از خودِ VPS `NXDOMAIN` نشون داد (درسِ #۱۱). کاربر ریشه رو پیدا کرد: تو پنلِ Cloud Host Iran رکورد رو با هاستِ اشتباه («panel» به‌جایِ «panel.liana») ساخته بود. بعدِ تصحیح، `certbot --nginx -d panel.liana.arefprojects.ir` موفق شد.

**نتیجه‌ی نهایی:** nginx reverse-proxyِ `panel.liana.arefprojects.ir` → `127.0.0.1:3001` با SSL، `pm2` (پروسه‌ی `liana-panel`) با `pm2 startup`+`pm2 save` پایدار شد.

**مشکلِ کوچیکِ آخر — «خالیه» (لیستِ خدماتِ VPS خالی بود):** `server/data/*.db` تو `.gitignore`ه (درسِ #۴۸) — دیتابیسِ لوکالِ کاربر و VPS دو فایلِ کاملاً مستقل بودن. **رفع:** کاربر مستقیم رو VPS `node scripts/import-site-services.mjs` رو اجرا کرد.
